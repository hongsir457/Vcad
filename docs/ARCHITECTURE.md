# VCAD 架构设计

## 总体数据流

```
原始图纸(分层实体流 JSON, 模拟 DWG/PDF 解析产物)
   │  parse_drawing()  ── 识图: 图层归类 + 标注解析 + 坐标吸附
   ▼
ParsedDrawing(轴网/楼层/柱/梁/墙/门窗/板 结构化构件)
   │  modeling_steps() ── 9 步模拟人工建模, SSE 逐步输出
   ▼
BuildingModel(三维实体 + 建模参数: 净长/净高/扣减明细 + 自检问题)
   │  qto_steps()      ── 7 步模拟手算, 每子目生成计算书
   ▼
BOQ(GB50500 十二位编码清单) + CalcSheet(计算书) + CrossCheck(双算复核)
   │
   ├─ 前端三列工作台(SSE 流式渲染步骤卡片 + three.js 模型 + 清单表)
   └─ 评测体系 benchmark/loop(与人工手算基准比对, 自动调参迭代)
```

## 事件协议(SSE)

`GET /api/run/{id}/stream` 每条 `data:` 为一个 JSON 事件:

| type | 含义 |
|---|---|
| `phase` | 进入新阶段(建模/算量) |
| `step_start` / `step_log` / `step_done` | 步骤开始/过程日志/完成(带摘要) |
| `result` | 最终载荷: `{model, boq, checks, params}` |
| `error` | 异常(转为可读消息) |

前端把事件折叠为 阶段 → 步骤卡片 树, 与 Claude Code 的工具调用流同构。

## 计量口径参数(可调参数 = 迭代循环的搜索空间)

| 参数 | 含义 | 正确值 |
|---|---|---|
| `snap_tol_mm` | 识图坐标吸附容差 | 2~5mm(吸收绘图误差, 保证稳定性) |
| `min_deduct_area_m2` | 墙体洞口扣减最小单孔面积 | 0.3(GB50854 规则) |
| `beam_to_column_face` | 梁长算至柱侧面 | 是 |
| `beam_height_to_slab_bottom` | 整浇梁高算至板底 | 是 |

朴素基线(全部关闭)综合分约 81; 迭代循环通过一阶爬山 + 二阶变异
(梁的两个口径参数须同时翻转才能提分, 单参数爬山会陷入局部最优)自动收敛至 100。

## 评价体系口径

- **准确率**: GT 条目中 偏差 ≤ 0.5% 的占比(逐用例平均)
- **召回率**: 1 − 漏项率; **精确率**: 1 − 多项率
- **稳定性**: 对每张图做 5 轮扰动重跑(实体乱序 + 坐标 ±1mm 抖动),
  清单签名 (编码, 项目特征, 数量) 完全一致的轮次占比
- **综合分** = 0.6×准确率 + 0.2×召回率 + 0.2×稳定性

基准答案(`eval/cases/*.gt.json`)为人工独立手算, 每条附 note 说明算式来源,
与系统实现解耦, 防止"自己出题自己改卷"。

## 扩展路线

1. **真实 DWG/PDF 输入**: 在 `drawing.py` 前增加解析适配层
   (ezdxf 读取 DWG 转实体流 / 多模态模型识别 PDF 图面), 产出同构 JSON 即可复用全链路。
2. **多层建筑**: `Level` 已支持多层, 需扩展实体的 `level` 归属与层间构件(楼梯/竖向连续墙柱)。
3. **更多清单子目**: 在 `qto.py` 的 `RULES` 注册表按同样模式增加
   (基础/钢筋/装饰/机电), 每个子目 = 一条规则 + 一个列式函数。
4. **地区清单**: `RULES` 可按 `region` 挂接地方定额/清单口径覆盖层。
5. **LLM 辅助识图**: 识图步骤(M1)的输入输出均为结构化 JSON,
   可将标注解析替换为大模型调用, 其余步骤保持确定性可复核。
