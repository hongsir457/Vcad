# VCAD 架构设计

## 总体数据流

```
输入层(任一):
  样例/上传 JSON ──────────────────────────────┐
  DWG/DXF ─ dwg2json.mjs (WASM LibreDWG,       │
             模型空间递归炸开块引用) ─┐          │
  PDF ──── pdf_import.py (矢量线段 + │          │
           原生文本 + 分块 OCR +     │          │
           比例标定) ────────────────┤          │
                                     ▼          │
                          通用实体流(mm 坐标)    │
                                     │          │
              识别器链(按序尝试, 全败给出诊断)    │
              ├─ steel_recognizer 钢结构平面     │
              └─ reinforcement_recognizer 柱加固 │
                                     ▼          ▼
                VCAD 原始图纸 JSON(分层实体流 + meta.recognition)
                                     │
   parse_drawing() ── 识图: 图层归类 + 标注解析 + 坐标吸附
                                     ▼
ParsedDrawing(轴网/楼层/柱/梁/墙/门窗/板/钢柱/钢梁/加固柱/管道/风管/桥架/设备)
                                     │
   modeling_steps() ── 模拟人工建模, SSE 逐步输出:
     M1 识图 → M2 轴网 → M3 楼层 → M4 柱 → M4b 加固柱 → M5 梁 → M6 墙
     → M7 开洞 → M8 板 → M10 给排水 → M11 暖通 → M12 电气 → M9 自检
                                     ▼
BuildingModel(三维实体 + 建模参数: 净长/净高/扣减/米重/假设 + 自检问题)
                                     │
   qto_steps() ── 模拟手算, 每子目生成计算书:
     Q1 定规范口径 → Q2 列项 → Q3 混凝土 → Q4 砌体/钢构/加固
     → Q5 门窗与模板 → Q5b 安装工程 → Q6 汇总编清单 → Q7 双算复核
                                     ▼
BOQ(带专业标签的清单) + 计算书 + CrossCheck + 待复核项
                                     │
   ├─ 前端三列工作台(SSE 步骤卡片 / three.js / 清单表 / 计算书 / 评测)
   └─ 评测体系 benchmark + loop(人工手算基准比对, 爬山+二阶变异自动调参)
```

## 事件协议(SSE)

`GET /api/run/{id}/stream` 每条 `data:` 为一个 JSON 事件:

| type | 含义 |
|---|---|
| `phase` | 进入新阶段(建模/算量) |
| `step_start` / `step_log` / `step_done` | 步骤开始/过程日志/完成(带摘要) |
| `result` | 最终载荷: `{model, boq, checks, params}` |
| `error` | 异常(转为可读消息) |

前端把事件折叠为 阶段 → 步骤卡片 树, 与 Claude Code 的工具调用流同构。

## API 一览

| 接口 | 说明 |
|---|---|
| `GET /api/drawings` · `GET /api/drawings/{id}` | 图纸列表(样例+上传)/原始实体 |
| `POST /api/drawings/upload` | 上传 DWG/DXF/PDF/JSON, 识别器链式尝试 |
| `DELETE /api/drawings/{id}` | 删除上传图纸(样例不可删) |
| `GET /api/run/{id}/stream` | SSE 流式执行流水线 |
| `GET /api/run/{id}/boq.csv` | 清单 CSV 导出(带专业列) |
| `POST /api/eval/run` · `POST /api/eval/loop` | 基准评测 / 自动迭代调参 |
| `GET /api/eval/history` · `GET /api/params` | 迭代生长史 / 当前口径参数 |

## 计量口径参数(评测迭代循环的搜索空间)

| 参数 | 含义 | 正确值 |
|---|---|---|
| `snap_tol_mm` | 识图坐标吸附容差 | 2~5mm(吸收绘图误差, 保证稳定性) |
| `min_deduct_area_m2` | 墙体洞口扣减最小单孔面积 | 0.3(GB50854 规则) |
| `beam_to_column_face` | 梁长算至柱侧面 | 是 |
| `beam_height_to_slab_bottom` | 整浇梁高算至板底 | 是 |

朴素基线(全部关闭)综合分约 81; 迭代循环通过一阶爬山 + 二阶变异
(梁的两个口径参数须同时翻转才能提分, 单参数爬山会陷入局部最优)自动收敛至 100。

## 评价体系口径

- **准确率**: GT 条目中 偏差 ≤ 0.5% 的占比(逐用例平均)
- **召回率**: 1 − 漏项率; **精确率**: 1 − 多项率
- **稳定性**: 对每张图做 5 轮扰动重跑(实体乱序 + 坐标 ±1mm 抖动),
  清单签名 (编码, 项目特征, 数量) 完全一致的轮次占比
- **综合分** = 0.6×准确率 + 0.2×召回率 + 0.2×稳定性

基准答案(`eval/cases/*.gt.json`, 共 4 个用例含全专业 case04)为人工独立手算,
每条附 note 说明算式来源, 与系统实现解耦, 防止"自己出题自己改卷"。

## 真实图纸识别: 迭代修复记录

评价体系(双算复核/自检/回归测试)在开发中实际抓出的缺陷, 均已修复并固化为测试:

| 轮次 | 缺陷 | 修复 | 回归测试 |
|---|---|---|---|
| DWG-1 | 型号表相邻行距 <500, 固定行高容差把编号配到邻行截面(双算偏差 98%) | 表头列带 + 最近基线 + 名义/理论米重 15% 语义校验 | `test_schedule_dense_rows_no_cross_match` |
| PDF-1 | 整页低倍 OCR 无法识别 CAD 小字号 | 5 倍高倍分块扫描 + 置信度过滤 | (真实图纸验证) |
| PDF-2 | 相邻两张加固表, 固定窗口/距离上限互吞编号 | 语义归属: 同行有截面尺寸=增大截面行; 近角钢型号+表标题=外包钢行 | `test_adjacent_tables_no_cross_swallow` |
| PDF-3 | 分块重叠产生残片("100"→"00")挤占尺寸列 | 提取端子串去重 + 解析端碎片合并与数值下限 | `test_ocr_fragment_rejected` |
| PDF-4 | 行容差 ±900 吞并相邻行(行距 800) | 收紧至 ±450 | 同上用例覆盖 |

图面缺失量(加固高度、"按实际"尺寸)一律显式假设 + 写入 `model.issues`,
在前端以待复核横幅呈现, 不做静默猜测。

## 扩展路线

1. **多层建筑**: `Level` 已支持多层, 需扩展实体 `level` 归属与层间构件(楼梯/竖向连续构件)。
2. **更多清单子目**: 在 `qto.py::RULES` 注册表按同样模式增加(基础/钢筋/装饰/防水),
   每个子目 = 一条规则 + 一个列式函数。
3. **地区清单**: `RULES` 按 `region` 挂接地方定额/清单口径覆盖层。
4. **识别器扩展**: 混凝土结构平面 DWG 识别(梁集中标注解析)、
   加固说明页层高表恢复(消掉加固高度假设)、缀板/新增钢筋计量。
5. **LLM 辅助识图**: 识别器输入输出均为结构化 JSON, 可将标注/表格解析替换为
   多模态模型调用, 其余步骤保持确定性可复核。
6. **异步上传**: PDF 含 OCR 约 3 分钟, 宜改为后台任务 + 进度事件。
